## 進め方の型

- **最初に1回：** 要件を箇条書きで渡す（盤面は座標）→ AI の質問に番号で答える → フェーズに分けて作り、1つずつ確認 → 遊べる形を早く作る
- **環境ごとにくり返す：** 人が遊ぶ・友人に遊んでもらう → 環境の変遷と強かったチームのファイルを渡す → 探索で「本当に強いか」を確かめる → 人が方針を決め、AI が数値を当てて測る → 完成したら環境を固定し、次の版へ

## うまくいったこと

- **要件を箇条書きと座標で渡した。** 盤面の形・隣接・前線で行き違いがなかった。質問にも A1〜E4 の番号で答え、仕様は1回のやり取りで固まった。
- **小さく区切って、そのつど確認した。** Phase 1 の「ペンタグラムの12マスが埋まらない」、Phase 3 の「(4,3) はペンタグラムが相手のとき以外は前線にならない」を、作り込む前に人が見つけた。
- **環境をバージョンで分けて固定した。** 面白かった環境を残したまま大きく作り変えられた。保存版はテスト（指紋）で守り、ストーリーとローグライトは Ver.2 に固定。
- **人の遊びの記録を渡した。** Ver.1 の「キングダム → 毒 → アグロ → 野生火力」の変遷と、強かったチームのファイル。数字だけでは分からない「結論構築」「意味のない駒」が分かった。
- **確かめる道具を、答えの分かっている所で試してから使った。** Ver.1 で、人が見つけたゴーレム城塞・道具増し野生と同じチームを、探索がゼロから見つけた。
- **ゲームの知識で探す数を減らした。** 下位互換だけの置き換え・隣にキャラのいない隣接道具・前線に効かない防御だけの道具。
- **「変えないこと」をはっきり言った。** 駒ごとに固定する部分と調整してよい部分。毒蛇は速度2以上、号令は重ねる、相性は極端でもよい。
- **調整を自動に任せきらなかった。** 勝率は整っても駒の個性が消える案を止められた。
- **時間の約束を書いた。** 締め切り（日本時間）・帰宅時間・スリープ。

## うまくいかなかったこと

| 起きたこと | 原因 | 次はこうする |

| Ver.1 の最強の確かめが弱かった（11/3）。ランダムなチームで探し似たチームを省いたため、道具増し野生が出ず、ゴーレム城塞より強い形も見落とした | 確かめ方を AI に任せた。AI も弱さを先に言わなかった | 確かめ方を先に決め、答えの分かっている例で試す。AI は近道の弱さを先に伝える |
| 説明が難しかった（11/5「正確に読み取れない」） | 専門用語・長い文・数字の並べすぎ | 最初から「やさしい日本語で、結論から」 |
| 探索のチーム名が番号だけ（11/5） | 読む人のことを考えていなかった | 出力の名前の付け方を最初に決める |
| 毒蛇の速度を2未満に下げた（11/7、AI の案） | 設計の約束が文書になく、AI は数字だけを見ていた | 約束を最初の設計メモに書き、AI は案の前に照らし合わせる |
| 報告が上位ばかり（11/7） | 報告の型を決めていなかった | 上位・下位・相性表・型が消えたとき・使われない駒を毎回入れる |

| 値段の付け方の前提がずれた（11/7「道具の基準キャラ」） | コスト式の前提（基準キャラ HP300・攻撃30・防御30）を見せていなかった | 式の前提を図や表にして、決める前に見せる |

## 指示の出し方の評価

◎ とても良い　○ 良い（少し足すともっと良い）　△ 直すと良い

- ◎ **最初の要件を箇条書きと座標で書いた**（11/2）。ストーリー・ローグライトを「バランスを取った後」とした順番も正しかった。
- ◎ **質問に番号で答えた**（11/2）。やり取りが1回で済んだ。
- ○ 「勝率75%くらいは許容する大雑把さで大丈夫です」（11/2）。合格の幅があると止めどきが分かる。次は：何を相手に測った勝率かも書く。
- △ 「計算量が膨大になりそうなので類似チームについては省いてよい」（11/3）。確かめが弱くなった。次は：「省き方を先に見せて」と頼む。
- ◎ **結果が変わらない切り落としを3つ出した**（11/4）。
- ◎ **締め切り・帰宅時間・スリープを書いた**（11/4〜）。
- ◎ 「分かりやすい日本語にしてください」（11/5）。
- ◎ **状態異常は1つだけ・新しい能力は増やしすぎない**（11/2・11/7）。AI は案を増やしがちなので、この線引きが効いた。
- ○ **Ver.3 の駒ごとの細かい指定**（11/7）。意図はよく伝わった。ただ「コスト固定で能力を足す」は式の上で両立しないことがあり、値段の係数を動かして他の駒にも波及した。次は：駒ごとに「コストと能力のどちらを優先するか」を決める。
- ○ 「内容的に問題はなさそうなので試算は不要です」（11/7）。その日のうちに切り出せたが、直後は麻痺（0.3倍）が強すぎて全チームに入った。次は：方針を決める前に短い試算（探索10分程度）。
- ◎ **調整の途中で線を引いた**（11/7）。「速度2を切ってる毒蛇は認められません」「ドワーフ磨きすぎです」「孤高の紋章が強すぎる」。次は：最初の設計メモにまとめる。
- ◎ **報告に入れてほしいことを指定した**（11/7）。形ごとの3チーム、相性表、Tier2、下位、型が消えたとき。次は：最初の探索の前に「報告の型」として決める。

## 人と AI の役割

- **人が強かったところ：** 面白いかどうかの判断、駒の個性・遊びの柱を守る、遊んだ記録、結果が変わらない切り落とし、「それは違う」と止める。
- **AI が強かったところ：** 仕様から画面・戦闘・保存までを短時間で作る、数十万〜百万チームの探索、相性表・均衡・型が消えたときの計算、過去の環境をテストで守る、夜の間の長い計算。
- AI は決めた数字に向かってまっすぐ調整する。数字に表れない「らしさ」は、人が先に言葉にしておく。

## 次のゲームで使う手順

1. 遊びの柱と「変えないこと」を1枚に書く（決着の時間、じゃんけんの関係、駒の個性、状態異常の数など）。
2. 目標の数字と、その測り方を決める（何を相手に測るかまで）。
3. 要件 → 質問への回答 → フェーズ分け → フェーズごとの確認。
4. 早く遊べる形にして、人に遊んでもらう。フィードバックは「環境の変遷」と「強かったチームのファイル」。
5. バランスを確かめる道具を先に作り、答えの分かっている所で答え合わせしてから使う。
6. データをバージョンで分け、遊ばれた版は固定してテストで守る。環境ごとに持つもの（チーム・自作駒など）を最初に一覧にする。
7. 調整は小さく。1回に1〜3か所、前後を同じ方法で測り、ぶれの大きさを先に知る。
8. 報告の型を決める（上位・下位・相性表・型が消えたとき・使われない駒・決着の時間）。
9. 人が止める場所を決める（看板の数値を変えるとき、全体に効く値を動かすとき）。
10. 長い計算は、締め切りと「寝る前にどこまで」を書く。
11. 見た目を差し替える時期を予定に入れる。

### 頼むときのひな形

```
■目的：何を作る・直すか
■変えないこと：駒の個性、遊びの柱、固定した環境 など
■目標：数字と、その測り方（何を相手に、何回測るか）
■任せてよいこと：数値の当てはめ、探索、テスト
■必ず確認してほしいこと：看板の数値を変える案、全体に効く値の変更
■報告に入れてほしいこと：上位・下位・相性表・使われない駒・型が消えたとき
■締め切り：日本時間 ○月○日 ○時（終わったらスリープ）
■説明：やさしい日本語で、結論から
```
