# Auto Battler 仕様書

> 数値はすべて初期値。Phase 7（バランス調整）で見直す。
> 「（調整）」が付いた項目は特に変わる前提。

## 1. 概要

ボードに駒（キャラクター・道具）を配置し、遺物を最大3つ持たせてチームを作る。
2チームが自動で戦い、プレイヤーは戦闘中に操作しない。

## 2. ボード

座標は `(行, 列)`。列が小さいほど前（敵側）。

| ボード | マス数 | コスト上限 | マス |
|---|---|---|---|
| ペンタグラム | 12 | 40 | (1,3) (2,1)(2,2)(2,3)(2,4)(2,5) (3,1)(3,2)(3,3)(3,4)(3,5) (4,3) |
| スクエア | 9 | 50 | (1,1)(1,2)(1,3) (2,1)(2,2)(2,3) (3,1)(3,2)(3,3) |
| ハニカム | 7 | 60 | (1,2)(1,4) (2,1)(2,3)(2,5) (3,2)(3,4) |

### 隣接

- **スクエア**：上下左右の4方向。
- **ハニカム**：同じ行で列±2、または行±1かつ列±1。中央(2,3)は6マスと隣接する（意図的）。
- **ペンタグラム**：三角形の向きは次のとおり。
  - (1,3)=△
  - 2行目 = ▽△▽△▽
  - 3行目 = △▽△▽△
  - (4,3)=▽
  - 同じ行で列±1は隣接。
  - 縦の隣接は (1,3)-(2,3)、(2,2)-(3,2)、(2,4)-(3,4)、(3,3)-(4,3) の4組のみ。

### 前線

- 各行で、列がいちばん小さい**キャラクター**を、その行の前線とする（道具は前線にならない）。
- キャラクターのいない行には前線がない。
- キャラクターは必ず1体以上配置する。

### 計算行（攻撃と防御の対応。Issue #21）

攻撃の当たり先と防御は「計算行」ごとに決める。ふつうは自分の行がそのまま計算行。ペンタグラム（4行）が**他のボード（3行）と向かい合うときだけ**、ペンタグラムの4行を3つの計算行へ振り分ける。ペンタグラムどうしは4行のまま。

| 計算行 | 振り分け元（ペンタグラムの行 × 割合） |
|---|---|
| 1行目 | 1行 × 1、2行 × 0.5 |
| 2行目 | 2行 × 0.5、3行 × 0.5 |
| 3行目 | 3行 × 0.5、4行 × 1 |

- **攻撃**：ペンタグラムの行の攻撃は、割合ぶんずつ各計算行へ分かれて当たる（2行目の攻撃は、1行目に半分・2行目に半分）。ダメージは割合を掛けたうえで、当たった計算行の防御で計算する。ほかのボードの攻撃がペンタグラムに当たるときは、攻撃側の行がそのまま計算行になる。
- **防御**：計算行の防御は、振り分け元の前線の防御を割合で重みづけした平均（例：計算行1 = (1行の前線の防御×1 + 2行の前線の防御×0.5) ÷ 1.5）。前線のいない行は平均に入れない。
- 計算行に前線が1つもないときは、いちばん近い計算行で代用する（同じ距離なら小さい行）。
- 防御のバランスがずれることは、編成の問題として扱う。
- 編成画面とデータ一覧で、計算行ごとの「攻撃/秒（実効攻撃×攻撃倍率×攻撃速度）」と「防御」を確認できる。

## 3. 駒

### キャラクター

| 項目 | 範囲（初期） | 説明 |
|---|---|---|
| コスト | 自動計算 | §6 |
| HP | 100〜1000 | チームHPに加算される |
| 攻撃 | 10〜100 | |
| 防御 | 0〜100 | 前線として攻撃を受けるときに使う |
| 攻撃速度 | 0.5〜3.0 | 1秒あたりの攻撃回数 |
| 特殊効果 | 0〜2個 | §5 から選択 |
| 種族 | 1つ | §4 |

### 道具

| 項目 | 説明 |
|---|---|
| コスト | 自動計算 |
| 攻撃 | 隣接するキャラクターの攻撃に加算 |
| 防御 | 隣接するキャラクターの防御に加算 |
| 特殊効果 | 0〜2個 |

道具自身は攻撃しない。前線にもならない。
道具の「攻撃時」効果（毒・麻痺）は、隣接するキャラクターの攻撃に付与される。

### 遺物

- マスを使わず、コストもかからない。1チームにつき最大3つ。
- 特殊効果だけを持つ（例：チーム全体の攻撃+10%）。

## 4. 種族シナジー（調整）

同じ種族のキャラクターが2体・3体・5体・7体以上いると、チームにボーナスが付く（満たした最大の段階だけが効く）。5体・7体は、マスの多いボード（ペンタグラム）で同じ種族を揃える利点のための段階。一覧はアプリの「データ一覧」でも見られる。

| 種族 | 2体 | 3体 | 5体 | 7体 |
|---|---|---|---|---|
| 戦士 | 種族の防御+15 | +30 | +50 | +75 |
| 魔導 | 毒付与量+1 | +1.5 | +2 | +2.5 |
| 獣 | 種族の攻撃速度+12% | +18% | +22% | +28% |
| 機械 | チームHP+10% | +20% | +35% | +50% |

**中立**：1体以上で、中立のキャラの攻撃+10%。種族ボーナスを駒のコストに織り込まず、別のパラメータで補うための種族なので、中立のキャラの能力はやや控えめにしてある。中立は「エルフ」「ドワーフ」「魔人」の3体（後ろの駒ほど高コストで強い）。他の種族は各6体。

## 5. 特殊効果

各効果は「種類＋パラメータ」の組で表す。駒作成では一覧から選んでパラメータを入力する。

| 種類 | 発動 | パラメータ | 内容 |
|---|---|---|---|
| 毒 `poison` | 攻撃が当たったとき | `stacks`（1〜10）、`chance` | 相手チームに毒を `stacks` 付与する。0.1秒ごとに「蓄積量 × 毒1蓄積あたりのダメージ（現在 0.25）」のダメージ。防御無視、戦闘終了まで続く、重ねがけで加算 |
| 麻痺 `paralyze` | 攻撃が当たったとき | `target`、`duration`(3s)、`chance` | 対象の攻撃速度を半減する。重ねがけで持続時間が延長される |
| 隣接攻撃倍率 `adjAtkMult` | 常時 | `mult`（例 0.2） | 隣接キャラクターの攻撃倍率を +mult |
| 行効果 `rowBuff` | 常時 | `stat`、`mode`、`value` | 同じ行にいるキャラクター（持ち主がキャラなら自分も）の `stat`（hp/atk/def/spd）に加算。`mode` は `add`（固定値。攻撃速度は不可）か `pct`（割合）。キャラ・道具に付けられる |
| 回復 `heal` | 一定間隔 | `amount`、`interval` | 自チームHPを回復（最大HPを超えない） |
| ステータス強化 `statBuff` | 常時 | `stat`、`value`、`mode`、`scope`、`tribe`（任意） | 遺物・種族ボーナス向け。`mode` は `add`（加算）か `pct`（割合）。`tribe` を指定するとその種族だけに効く |
| 毒付与量 `poisonBonus` | 常時 | `value` | 種族ボーナス専用。毒の付与量に加算 |

**麻痺の `target`**（効果ごとに選ぶ）
- `front`：攻撃した相手の前線
- `random`：敵キャラからランダム
- `fastest`：攻撃速度が最も高い敵
- `strongest`：攻撃が最も高い敵

ランダム要素はすべてシード付き乱数を使い、同じ入力からは必ず同じ結果が出るようにする。

## 6. コスト計算（調整済み）

係数はすべて `src/data/balance.js` にある（調整は §11）。

```
実力（キャラ） = HP/400 + 攻撃×攻撃速度/40 + 防御/55 + Σ効果の実力
実力（道具）   = 攻撃/16 + 防御/25 + Σ効果の実力
コスト         = 1.3 × 実力 ^ 1.6   を整数に四捨五入（最低 1）
```

- 実力の指数が1より大きいので、**高い駒ほど割高**になる。これで、マスが少なくコスト上限の高いボード（ハニカム）と、マスが多くコスト上限の低いボード（ペンタグラム）が釣り合う。
  - 指数が1（比例）だと、上限20・25・30の差がそのまま戦力の差になり、ハニカムが一方的に強くなる。
- 小数点以下は四捨五入。切り上げにすると、安い駒ほど割高になって偏る。
- チームのコストは駒のコストの合計。以前は0.5刻みだったが、小数を避けるため全体を2倍にして整数にした（ボードの上限も2倍：40 / 50 / 60）。

効果の実力：

| 効果 | 実力 |
|---|---|
| 毒 | 0.5 × stacks × chance |
| 麻痺 | 1.0 × chance |
| 隣接攻撃倍率 | 4.5 × mult |
| 回復 | 0.1 × amount / interval |
| 行効果 | 3 × 基準キャラ（HP300・攻撃30・防御30・速度1）への上昇分の実力（HPは value/400、攻撃は value/40、防御は value/55。割合は基準値に掛ける）。3 は同じ行にいる想定人数 |

## 7. 戦闘

### チームHP

- 最大HP = 全キャラクターのHPの合計（＋ボーナス）。
- キャラクターは個別には倒れない。

### 進行

- 0.05秒刻みの固定ステップで、最大30秒（600ステップ）進める。
- 各キャラクターは `1/攻撃速度` 秒ごとに攻撃する。麻痺中は攻撃速度が半分になる。
- 同じステップ内のダメージ・回復は、両チームぶんを集計してから同時に適用する（先攻・後攻の有利をなくすため）。

### 攻撃

- **対象**：攻撃者と同じ（計算）行にいる敵の前線。その行に前線がいなければ、いちばん近い行の前線を狙う（同じ距離なら行番号が小さい方）。ペンタグラムが絡むときは「計算行」（§2）で決める。
- **ダメージ** = `攻撃(実効) × 攻撃倍率 × 100 / (100 + 対象の防御(実効))`
  - 攻撃(実効) = 基本値 + 隣接道具の攻撃 + 種族・遺物などのボーナス
  - 防御(実効) = 基本値 + 隣接道具の防御 + 種族・遺物などのボーナス
- **毒**：0.1秒ごとに、相手チームHPから蓄積量ぶん減らす。

### 実装上の取り決め（Phase 2）

- 実効ステータス = `(基本値 + 隣接する道具 + 加算バフ) × (1 + 割合バフの合計)`。隣接攻撃倍率は実効攻撃とは別に掛ける（`1 + Σmult`）。
- 最初の攻撃は戦闘開始から `1/攻撃速度` 秒後。以降その間隔で攻撃する（麻痺中は間隔が2倍）。
- 1ステップの処理順：
  1. 攻撃する駒を決める（麻痺の判定はステップ開始時点のもの。このステップで付いた麻痺は次のステップから効く）
  2. 攻撃を解決（ダメージ計算、毒・麻痺の抽選。先攻・後攻の有利が出ないよう、ダメージは溜めてから反映する）
  3. 毒の継続ダメージ（偶数ステップ＝0.1秒ごと）
  4. 回復
  5. 両チームのダメージ・回復を同時に反映（最大HPで頭打ち）→ 決着判定
- 毒は「攻撃を受けたチーム」に蓄積する。付与量は `stacks + 毒付与量ボーナス（魔導シナジー）`。
- 麻痺の持続は 0.05 秒単位に丸める。かかっている間に再度当たると、残り時間に持続時間が加算される。
- 乱数は確率の判定とランダム対象の選択だけに使う。シードが同じなら結果とログは完全に一致する。
- `fastest` / `strongest` は、麻痺中かどうかに関係なく実効攻撃速度・実効攻撃で比べる（同値なら先に配置された駒）。

### 勝敗

1. 片方のHPが0以下になった時点で、そのチームの負け。
2. 同じステップで両チームとも0以下になった場合は、`HP/最大HP`（負の値になる＝はみ出した割合）が高い方の勝ち。
3. 30秒経過時は、`HP/最大HP` が高い方の勝ち。
4. 2・3で値が完全に同じなら引き分け。

### バランス目標

- 平均的な対戦が約10秒で決着する。
- 特定の駒・ボードの勝率が突出しない。
- 駒は今後増える・自作もされるので、完璧ではなく「基準になる数値」を目指す（§11）。

## 8. ゲームモード

| モード | 内容 |
|---|---|
| 駒作成 | オリジナルのキャラ・道具を作成・保存。チーム編成で使用可。JSON入出力 |
| チーム編成 | ボード選択・配置・遺物。9スロット保存。JSON入出力 |
| カスタム対戦 | 両チームを自分で選んで対戦 |
| ランダムマッチ | 自チーム vs ゲーム側のプリセットチーム |
| ストーリー | バランス調整後に設計 |
| ローグライト | バランス調整後に設計 |

### 観戦画面（Phase 3）

- 左のチームをA、右のチームをBとし、前線が中央を向くよう、Aの盤面だけ左右反転して描く。
- 戦闘エンジンを `createBattle` で0.05秒ずつ進めて再生する。画面独自の計算はしない。
  - 攻撃：攻撃側のマスが光り、受けた側のマスが赤く光ってダメージ数値が浮かぶ
  - 麻痺：対象のマスが青い破線になり、❄が浮かぶ
  - 毒：HPバーの下に蓄積量を表示する
  - 回復：HPバーが緑に光る
- 操作：対戦開始／一時停止・再開／結果までスキップ／速度（0.5・1・2・4・8倍）／シード指定。
- 同じチームとシードなら毎回同じ戦闘になる。ログと結果（勝者・決着の理由・時間・HP割合・与ダメージ）を表示する。
- マスにマウスを乗せると、その駒の実効ステータス（隣接する道具・バフ込み）を表示する。
- 毒の継続ダメージはログに出さない（0.1秒ごとで多いため）。

## 9. 保存とJSON

- 保存先は localStorage（キー `auto-battler.teams.v1`）。使えない環境では、そのページを開いている間だけ覚える。
- 入出力は、ファイルのダウンロード／読み込みとクリップボード（コピー・貼り付け）の両方に対応する。
- 読み込み時に形式チェックを行い、不正なJSONは理由を表示して拒否する。
  - 拒否するもの：JSONとして壊れている、`format`・`version` が違う、ボードが不正、盤面にないマスや重複したマス、自作駒の範囲外の値・ID重複・標準の駒とのID衝突、`__proto__` のような危険な名前、サイズ超過（100万文字）。
  - 拒否せず読み込むもの：コスト超過・キャラ不在などの「ルール違反」。編成画面に理由が出るので、直してから使う（対戦には使えない）。
  - 知らない項目は取り込まない。
- メモ帳などで手編集したJSONや、改ざんされた保存データが入ってきても安全なように、駒・チームの両方で次を守る（`src/storage/pieceJson.js`、`teamJson.js`）。
  - 既知の項目だけをコピーする（`__proto__`・`constructor`・未知の項目は捨てる）。辞書は `Object.hasOwn` で引く。
  - 型と範囲を検査する（数値は有限で範囲内、整数が必要なものは整数、文字列は長さ上限）。`1e999` のような無限大も拒否。
  - ID（駒・遺物）は `[A-Za-z0-9_-]` の64文字以内で、`__` で始まらない。自作駒のIDは標準の駒と重複させない。
  - 名前・アイコンに制御文字と、表示を偽装できる文字（右から左への切り替えなど）を使わせない。アイコンには `< > & " ' `` ` `` も使わせない。
  - 表示するときは、名前・アイコンを必ずHTMLエスケープする。
  - 特殊効果は種類ごとの項目だけを残し、個数（2個まで）と数値の範囲を検査する。駒に付けられない効果（遺物用の強化など）は拒否。
  - 配列の長さ（マス64、遺物10、自作駒100、駒JSON100）と、JSON全体の大きさ（100万文字）に上限を設ける。
  - 保存庫の読み込み時にも同じ検査をし、壊れた駒・チームは読み飛ばす（空きとして扱う）。

### 駒のJSON

```json
{ "format": "auto-battler/piece", "version": 1, "piece": { "...": "§9 の駒" } }
{ "format": "auto-battler/pieces", "version": 1, "pieces": [ { "...": "..." } ] }
```

- 1つの駒、またはまとめて（最大100個）。1つでも不正なら全体を拒否する。
- 取り込み時、同じIDの駒がすでにある場合：内容が同じなら何もしない。違うときは確認し、「上書き」か「別の駒として追加（新しいID）」を選べる。

### ランダムマッチ（Phase 6）

- 「対戦」タブの「ランダムマッチ」。自分のチーム（プリセットか保存スロット）と、ゲーム側が用意した対戦相手で戦う。観戦・倍速・スキップはカスタム対戦と同じ。
- 相手は強さ（やさしい／ふつう／つよい／おまかせ）を選んで抽選する。「🎲 相手を抽選」で引き直せる。直前の相手は、ほかに候補があるかぎり避ける。
- 相手になるのはプリセットだけ（自分が保存したチームは出ない）。
- 戦うたびに新しいシードを使う。同じ相手でも毎回展開が変わる。結果の欄にシードを出すので、同じ戦いは、カスタム対戦にシードを入れて再現できる。
- ページを開いている間の戦績（勝・敗・分）を表示する。保存はしない。
- プリセットは9チーム（3ボード × 3段階）。同じボードの中では、やさしい < ふつう < つよい の順にコストが高く、構成も整っている。強さの初期評価は総当たりで、勝率の平均が やさしい 約12%、ふつう 約58%、つよい 約80%。個別のばらつきは Phase 7 で調整する。

### 駒作成（Phase 5）

- キャラクター・道具を作成して保存（localStorage、キー `auto-battler.pieces.v1`、最大200個）。同じ画面で編集・複製・削除できる。
- ステータスはスライダーと数値入力。範囲は §3 の表のとおり。高いほどコストが大きくなり、内訳（HP・攻撃×速度・防御・効果）と合計を画面に出す。
- 特殊効果は一覧（毒・麻痺・隣接攻撃倍率・回復）から選び、最大2個。毒の付与量は1〜10。
- 名前は1〜30文字、アイコンは記号・絵文字（8文字以内、`< > & " ' `` ` `` を含まない）。IDは自動で振る（`u_` + ランダム）。
- 範囲外の値がある間は保存・書き出しできない。
- 作った駒は、チーム編成の駒パレットに「破線の枠」で出る。
- チームに置いた自作駒は、**置いた時点の内容がチームにコピー**される。あとで駒作成で直しても、保存済みのチームは変わらない。編成画面に「新しい版があります」と出るので、「最新版に更新」を押すと取り込める。
- 削除した駒も、チーム側のコピーが残るので、チームは壊れない。

### チーム編成（Phase 4）

- 保存スロットは9つ。スロットを選んで「保存」。別のチームが入っているスロットは、上書き前に確認する。
- 編成画面でできること：チーム名、ボード選択（盤面にないマスの駒は外れる）、駒の配置（駒を選んでマスをクリック、右クリックで外す）、遺物3枠、コスト表示。コスト超過のまま保存はできるが、対戦には使えない。
- 保存時、自作駒は使っているものだけをチームに同梱する（Phase 5 で自作駒の保存庫を追加する）。
- 対戦タブ（カスタム対戦）の選択肢は「プリセット + 保存済みスロット」。

```json
// 駒
{ "format": "auto-battler/piece", "version": 1,
  "piece": { "id": "u_xxx", "kind": "character", "name": "見習い剣士", "icon": "🗡️",
    "hp": 300, "atk": 40, "def": 30, "spd": 1.0, "tribe": "warrior",
    "effects": [ { "type": "poison", "stacks": 1, "chance": 0.5 } ],
    "sprite": null } }

// チーム
{ "format": "auto-battler/team", "version": 1,
  "team": { "name": "チームA", "board": "square",
    "slots": [ { "pos": [1,1], "pieceId": "c_swordsman" } ],
    "relics": ["r_whetstone"],
    "customPieces": [ ] } }
```

- チームJSONには、使用している自作駒の定義を `customPieces` として同梱する。他人のチームを取り込んでも動くようにするため。
- `sprite` は将来のドット絵用（§10）。

## 11. バランス調整（Phase 7）

### 調整ツール

```
node tools/balance.js                          ランダムなチーム同士を3000戦して、集計を出す
node tools/balance.js --matches 20000 --seed 2 戦数・乱数の種を変える（同じ種なら同じ結果）
node tools/balance.js --mode presets           プリセット同士の総当たり
node tools/balance.js --brief 1                要点を1行で出す（試行を重ねるとき用）
node tools/balance.js --set damageScale=0.8 --set cost.curve=1.5
                                               src/data/balance.js の値を一時的に変えて試す
```

- ランダムなチーム：ボードを選び、コスト上限と1マスあたりの予算に合わせて駒を選ぶ。道具は、効く相手（隣のキャラクター、防御の道具なら前線）が多いマスに置く（`src/core/randomTeam.js`）。
- 出力：決着時間（平均・10%点・90%点）、決着の理由、毒の割合、ボード別・種族シナジー別・駒別・遺物別の勝率、目標から外れている項目。
- 1万戦は数秒で終わる。

### 調整後の数値（`src/data/balance.js`）

| 項目 | 値 | 意味 |
|---|---|---|
| `damageScale` | 1 | 通常攻撃のダメージにかける倍率（テンポ調整用。今は等倍） |
| `poisonDamage` | 0.25 | 毒1蓄積あたりの、0.1秒ごとのダメージ |
| `poisonDuration` | なし | 毒1回分が続く秒数（なしなら戦闘終了まで） |
| `paralyzeFactor` | 0.5 | 麻痺中の攻撃速度の倍率 |
| `cost.*` | §6 | コスト式の係数 |

### 調整の経過と結果

調整前（標準の駒がコスト1〜3、整数に切り上げ、毒は1蓄積1ダメージ）は、次の問題があった。

- 平均決着が6.6秒で短く、与ダメージの約4割が毒だった。
- ハニカムは、標準の駒のコストが低くて上限30を使い切れず、勝率33%と弱かった。
- 魔導3体のシナジーが勝率74%と突出していた。

対応：

1. **毒を弱めた**（1蓄積あたり 0.25）。毒は防御を無視して溜まり続けるので、決着が速くなりすぎていた。
2. **上級の駒を追加した**（キャラ5体・道具3個）。ハニカムが上限を使い切れるようにするため。
3. **コスト式を変えた**。切り上げ → 四捨五入、整数 → 0.5刻み、実力に指数1.6を掛けて高い駒ほど割高にした。ボード間の勝率の差がいちばん縮まった組み合わせ。
4. **種族シナジーを弱めた**（獣3体 +30% → +22%、魔導3体 毒+2 → +1.5）。
5. 個別の駒・遺物を調整した（毒蛇・見習い魔導士の毒の確率を下げる、道具を強くする、将軍を調整する、砥石・砂時計を弱める）。
6. プリセット9チームを、新しいコストで予算を使い切る構成に作り直した。

結果（ランダムなチーム 2万戦）：

| 項目 | 目標 | 結果 |
|---|---|---|
| 平均決着時間 | 8〜12秒 | 10.7秒（10%点 6.3秒、90%点 16.0秒） |
| 時間切れ | — | 0.2% |
| ボード別の勝率 | 45〜55% | ハニカム 55.2%、ペンタグラム 48.5%、スクエア 46.2% |
| 種族シナジー | — | 48〜58%（3体の段階も 54〜58%） |
| 駒別の勝率 | 40〜60% | 標準の駒はほぼ 40〜58% |

### 既知の偏り（基準として許容する）

- **道具が弱く出る**（木の盾・回復薬・軍旗 35〜39%、王冠・聖鎧・魔剣はさらに低い）。道具は隣のキャラクターに効く駒で、置き場所で価値が変わる。ランダム生成は置き方が粗いので、実際より弱く出ている。高い道具（魔剣・聖鎧・王冠）は、生成の都合で標本が少なく（150〜400戦）、数字が当てにならない。
- **プリセットは決着が速い**（平均4〜5秒）。人が組むと、中央のマスに隣接攻撃倍率の道具を置くなど、ランダムより効率のよい構成になるため。「機械工廠」（つよい）は勝率が高すぎる。
- 平均決着時間は、チームの組み方で大きく変わる。駒が増えたら、`node tools/balance.js` で測り直す。

### 戦闘面の見直し（Phase 7 追補）

ペンタグラムの計算行（§2）、コスト2倍化（§6）、5体・7体シナジーと中立（§4）、行効果（§5）、駒の増員（各種族6体＋中立3体）を入れたうえで測り直した。

| 項目 | 目標（許容は75%程度まで） | 結果（ランダムなチーム2万戦） |
|---|---|---|
| 平均決着時間 | 8〜12秒 | 11.3秒（時間切れ0.3%） |
| ボード別の勝率 | 45〜55% | ハニカム 50.1%、ペンタグラム 55.7%、スクエア 44.3% |
| 種族シナジー | 〜75% | 5体は62〜76%（魔導7体 77%、獣7体は標本が少なく87%） |

調整したもの：5体・7体シナジーの値（獣・魔導を抑えた）、行効果のコスト係数（2→3。行効果付きの安い駒が強すぎたため）。

既知の偏り：獣・魔導は安い駒が多く、数を揃えやすいため5体以上が強い。プリセットは平均4秒台で速く、ハニカムが強め（62%）でペンタグラムが弱め（40%）。いずれも許容範囲として、駒が増えた後に測り直す。

## 12. 対戦環境（バージョン）

調整を続けながら、過去の環境もそのまま遊べるようにする。**環境** = 駒・種族シナジー・遺物・プリセットチーム・ボードのコスト上限・バランス値（`balance.js`）の組。

| 環境 | 中身 | 保存チームの場所（localStorage） |
|---|---|---|
| Ver.1（保存版） | `src/data/environments/v1.js` に固定したコピー。手で直さない | `auto-battler.teams.v1`（環境を分ける前からの保存先） |
| Ver.2（調整中・最新） | いつものデータファイル（`pieces.js`・`tribes.js`・`relics.js`・`presetTeams.js`・`balance.js`・`boards.js` のコスト上限） | `auto-battler.teams.v1@v2` |

- 画面上部の「環境」で切り替える。切り替えるとページを読み込み直す。選んだ環境はブラウザに覚える（`auto-battler.env`）。初めての人は最新の環境。
- 対戦は同じ環境のチーム同士だけ。ボード・ルール（ダメージ式・計算行など）の仕組みは全環境で共通で、変わるのは数値とデータ。
- 初めて開いた環境には、1つ前の環境の保存チームをコピーする（Ver.2 を初めて開くと Ver.1 のチームが入っている）。保存先がまだ一度も作られていないときだけで、前の環境のチームはそのまま残る。コピーしたときはホームに一度だけお知らせを出す。
- 保存チーム（9スロット）は環境ごとに別。自作駒は全環境で共通（コストはその環境の式で計算し直す）。
- チームのJSONには作った環境（`env`）が入る。別の環境のJSONも読み込めて、そのときは「Ver.1で作られたチームです」と案内する。環境を他へ移したいときはJSONで書き出して読み込む。
- 仕組み：`src/data/environment.js` の `applyEnvironment(id)` が、各データファイルが export しているオブジェクト・配列の中身を入れ替える。
- バランス調整ツールは `node tools/balance.js --env v1` で過去の環境を測れる。

**新しいバージョンを切るとき**（例：Ver.2 を固定して Ver.3 の調整を始める）
1. `node tools/snapshot-env.js v2 "Ver.2"` → `src/data/environments/v2.js` ができる
2. `src/data/environments/index.js` の `SNAPSHOTS` に v2 を足す
3. `src/data/environment.js` の `LATEST` を `id: 'v3', name: 'Ver.3'` にする（Ver.3 の保存チームは新しい場所になる）
